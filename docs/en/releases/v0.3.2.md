# KOReader Ecosystem v0.3.2

[English](v0.3.2.md) | [Português (Brasil)](../../releases/v0.3.2.md)

## What's new

- Settings shows the local Hardcover action queue and separates safe actions from actions that require manual review.
- Reconciliation requires explicit confirmation, uses an atomic claim to prevent concurrent sends, and processes at most four actions per click.
- Actions that were never sent can be submitted once after confirmation. If an earlier submission has an uncertain result, only updates to an existing read or rating may be retried because they are idempotent.
- A new read and a journal note with an uncertain result stay in manual review; the app never resends them automatically.
- Documentation now distinguishes the delivered reconciliation flow from background page prefetch and physical plugin-limit validation, which remain pending.

## Limits

- Reconciliation is manual and uses small batches; the app does not automatically drain the queue in the background.
- The existing Hardcover cache keeps fetched pages and current reading for up to 30 days after transient failures. Incremental prefetch is not implemented.
- Settings currently shows aggregate queue counts; per-book/action details and individual resolution of manual-review items are not available yet.
- Local code caps the app at 1,000 requests per rolling 24 hours and the plugin patch at 2,000 per 24 hours. Website and other client usage share the account quota and cannot be observed by the app; plugin installation/counter behavior still needs Kindle validation.
- Real KOReader–Hardcover synchronization and plugin installation still need physical-device validation.
- The installer is not digitally signed.
